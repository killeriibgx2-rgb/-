# 2.11.0 — системная оптимизация по dCpi35wHoy и thermalstats

Основание: 98.25% серверного профиля в тепле, 1.55 млн ячеек / 4 млн связей,
рост ~513 ячеек/обновление. Задача выполняется без промежуточных сообщений автору.

## Численное ядро

Мировой адаптер использует новый консервативный интегратор: симметричное расщепление
на точные двухъячеечные обмены и точный оператор внешней границы/мощности.
Для пары C1,C2,G и полуинтервала h:
q=(T2-T1)*(1-exp(-G*(1/C1+1/C2)*h))/(1/C1+1/C2).
Одна сторона получает q, другая теряет q. Пассивный обмен не выходит за диапазон
исходных температур. Граничный оператор решает C*dT/dt=P+G*(Tout-T) аналитически.
Проход вперёд/назад симметричен; два интервала по 0.25 s дают прежние 0.5 s
физического времени. Это НЕ ограничение числа подшагов явного Euler: изменён метод.
Погрешность расщепления остаётся, пространственного направления скорости воздуха нет.
Коэффициенты экспоненты кэшируются с инвалидацией при смене G/C и интервала.
При изменениях только источника/погоды вычислять экспоненты рёбер снова не нужно.
Старый явный метод остаётся для регрессионных сравнений, но не вызывается миром.

## Обход мира и индексы

- Мощный источник заполняет радиус 2 один раз, а не 125 запросов каждый полусекундный
  шаг. Повторная проверка при изменении источника/выгрузке соседнего чанка;
  незавершённый из-за отсутствующего чанка ореол не помечается готовым.
- pending и очередь сканирования дедуплицированы; выгрузка удаляет запись сканирования.
  За тепловой шаг проверяется максимум 128 pending, один чанк сканируется на источники.
- Контакты с погодой и геотермальная формула кэшируются по столбцам. Любой setBlockState
  в столбце инвалидирует его даже при изменении блока вне графа (например, крыша).
  Погода и высотная поправка обновляются без поклеточных запросов мира.
- Состояния блоков обновляет обязательный mixin LevelChunk; резервный обход ограничен
  4096 состояниями за шаг, а не полным миром. Изменения через штатный setBlockState
  не ждут этого резервного обхода.
- Загруженность проверяется один раз на чанк перед шагом; сохранение результатов
  использует полученный флаг. Поиск блоков по-прежнему не загружает новые чанки.
- Внешняя граница расширения выделена в отдельную очередь, а не ищется полным
  сканированием внутренних 1.5 млн ячеек. Бюджет добавлений строго <=512, проверка
  кандидатов <=4096 за шаг.
- Расширение требует пространственного градиента со стороны уже известных соседей
  либо работающего источника, а не только разницы с новой погодой. Простая равномерная
  смена наружной температуры больше сама не запускает цепочку новых ячеек.
  Порог 0.25°C является приближением границы численного домена, а не удалением данных.

## Очистка и сохранения

- При выгрузке измерения удаляется его Workspace; остановка сервера как прежде очищает всё.
- Snapshot проверяет уникальность примитивным LongOpenHashSet без boxed Long.
- Тление костров не тратит время в выгруженных чанках.
- Версия теплового сохранения прежняя; никакие температуры не удаляются/не сбрасываются.

## Честные границы

Полноценное секционное засыпание и дисковое вытеснение SavedData НЕ внедрены:
оно требует решения граничного потока и контролируемой ошибки, а не случайного радиуса.
Старые сохранённые ячейки продолжают участвовать, но без глобального CFL-цикла.
Внешнее расширение при физически значимом пространственном градиенте всё ещё возможно.
Правки направлены на численный, пространственный, событийный и lifecycle-расходы,
а не обещают устранение всех возможных утечек/гарантированные 20 TPS.

## Проверки

Новый метод: аналитическое решение пары/границы, энергия, отсутствие выбросов,
пауза выгруженного соседа, добавление связей/изменение C после кэширования,
сходимость к мелкому явному шагу, закрытая комната и допустимое отличие <=1°C
в точках теста, миллион ячеек. Старые тесты явного ядра сохранены.
Frontier: равномерная смена погоды не расширяет домен, градиент от источника — расширяет.
Нужна проверка в мире автора; синтетический тест не равен TPS Minecraft.
