# 2.12.0 — адаптивная модель вместо миллионов постоянно активных блоков

Автор разрешил переписать логику ради результата. Главный осознанный компромисс:
поблочная точность рядом с игроком, приближённый конечный объём вдали.
Это не заявление о полноценной аэродинамике и не отключение далёких источников.

## Представление

- Тайлы 8×8×8. В окрестности игрока (3×3×3 тайла, 24 блока по каждой оси,
  привязка к сетке) — 512 отдельных узлов/тайл. Без наблюдателя — один узел/тайл.
- 10 секунд удержания подробности после ухода, чтобы избежать дрожания режима.
- Источники всех видов, включая лаву/магму и удалённые печи, продолжают подавать мощность.
- Крупный узел хранит суммарную теплоёмкость, среднюю с весом C температуру и
  эффективную проводимость. Крупный контакт: площадь 64, две полудлины по 4.
  На fine/coarse границе 64 отдельных контакта, длины .5 и 4; один и тот же поток
  отнимается с одной стороны и добавляется другой.
- Сохранённые индивидуальные температуры не становятся автоматически миллионами
  solver-узлов. Сохраняется массив 512 значений + масштаб/сдвиг остаточных различий.
  Крупный шаг изменяет среднее с сохранением энергии; внутренние различия затухают.
  Ограничитель остатка не допускает новых экстремумов за пределами прежних значений
  и новой средней. При детализации нет сброса к погоде.
- Удалённая комната внутри одного тайла больше НЕ описывается точной стеной: материал
  усреднён. При возвращении игрока поблочные стены возвращаются в расчёт. Это цена
  уменьшения вычислений, а не скрытая точная симуляция.

## Миграция/жизненный цикл

- SavedData v2 читает v1. Старые sparse-ячейки мигрируют по тайлам с точным переносом
  существующих значений. Не посещённые старые данные остаются в legacy-части файла.
- Новый формат сохраняет coarse-остаток, не разворачивая его при каждом тике.
  Старые версии модификации не должны открывать мир после записи v2: нужен бэкап.
- Выгруженные чанки исключаются из графа, сохраняют температуры и не догоняют время.
- Простой запрос термометра/моба/снега больше не создаёт ячейки.
- Инициализация: до 64 срочных тайлов и 16 фоновых за шаг, без загрузки чанков;
  ранее неактивный тайл начинает расчёт после инициализации, без catch-up.
  Это очередная начальная подготовка, а не замедление шага уже активных тайлов.
- Крупное расширение — до 4 тайлов за шаг; источник/пространственный градиент,
  а не только равномерная смена погоды. Погода обновляет существующие объёмы.
- Сканирование источников новых чанков продолжается отдельно; подробная зона игрока
  сразу обнаруживает свои источники при материализации, не ждёт общей очереди.

## Контроль

thermalstats: nodes (активная задача), fineCells, coarseTiles, retained/legacy
(сохранённые подробности), edges, substeps, initialized, время расчёта/подготовки,
rebuilds, sources, queued. Размер сохранения не равен размеру решателя.

Нужны тесты переходов coarse/fine, смешанной границы, сохранения C*T, паузы,
миграции v1 и повторного сохранения v2, многих тысяч удалённых тайлов и долгого
простого без игроков. TPS Minecraft не выводится из одного синтетического таймера.
