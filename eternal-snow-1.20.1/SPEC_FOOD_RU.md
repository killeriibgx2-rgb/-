Версия: **2.7.1**. Реализовано и собрано CI.

> **2.7.1:** в печи больше нет инъекции в `burn`. Ваниль сама кладёт готовое в слот 2, а `serverTick` TAIL возвращает предмет в слот 0 и ставит метку «оттаяло». Статический обработчик — обязательное условие: миксин 0.8.5 сверяет статичность точно, а `burn` в ванилле статический, в Forge — нет. ## 1. Заморозка: закон Ньютона

```
T(t) = T_места + (T_предмета − T_места) · e^(−t / τ)
τ = 232.4 с = 4648 тиков
```

Якорь задан владельцем: **при −35 °C мясо мёрзнет за 3:00** (от температуры тела +36.6 до порога −2).

Проверенные числа (`FoodState.java`):

| Температура места | Заморозка (из +36.6 до −2) |
|---|---|
| −35 °C | **3:00** |
| −30 °C | 3:21 |
| −20 °C | 4:26 |
| −10 °C | 6:49 |
| −5 °C | 10:11 |

Разморозка (из −20 до +3):

| Место | Время |
|---|---|
| Дом +20 | 3:19 |
| Костёр +45 | 1:42 |
| Печь +100 | **0:50** |
| Печь +100 из −40 | 1:25 |

## 2. Что хранится в теге

```
eternalsnow_food: { t: °C (шаг 3), s: 0..4, p: 0..999, u: gameTime последнего скана }
```

- **`t` кратен 3** — это и есть «погрешность 2–3 градуса». Ванильный `isSameItemSameTags` сравнивает тег целиком, поэтому еда из одного места получает одинаковые `t`/`u` и **склеивается сама**. Миксин на склейку не нужен.
- **`s`** — ступень порчи: 0 свежее, 1 лежалое, 2 несвежее, 3 протухшее, 4 гниль.
- **`p`** — прогресс текущей ступени (промилле), сбрасывается при переходе.
- **`u`** — штамп времени: весь контейнер сканируется одним проходом, поэтому у всего мяса в сундуке одинаковый `u`.

Замороженность **не хранится флагом** — выводится из `t ≤ −2`. Гистерезис: замёрз при `≤ −2`, оттаял при `≥ +3`, между ними не меняется.

## 3. Порча

```
очки += dt / (ticksPerStep · тип) · clamp(T/20, 0, 3)
```

- при `T ≤ 0` множитель = 0 → **в холоде не портится вообще**;
- 1000 очков = одна ступень; 5 ступеней = гниль.

| Тип | Одна ступень при +20 | До гнили при +20 |
|---|---|---|
| Сырое мясо | 12 мин | 60 мин |
| Рыба | 18.5 мин | 92 мин |
| Приготовленное | 21.6 мин | 108 мин |
| Сухое (хлеб, печенье) | быстро (1 ч) | 5 ч |
| Консервы (напитки, карамель, золотое яблоко) | не портится | — |

Классификация — **теги**, не хардкод: `eternalsnow:foods/{raw_meat, fish, cooked, dry, produce, preserved}`, с `"required": false` для `farmersdelight:*`.

## 4. Где обновляется

Проход раз в **200 тиков (10 с)**, горячий список:

- инвентарь игрока (`Inventory.items` уже включает броню и оффхенд) + эндер-сундук → окружение = **тело +36.6**;
- открытые контейнеры → окружение = температура блока;
- полки рядом с игроком → температура блока.

Незагруженный сундук не стоит ничего: при следующем визите `FoodState.scan` интегрирует всё прошедшее время одной формулой. Прошедшее время ограничено тремя τ — дальше предмет уже равен среде.

Тика на предмет нет вообще.

## 5. Печь (миксин `AbstractFurnaceBlockEntityMixin`)

- `canPlaceItem(0)` → **один предмет за раз** (и для воронок тоже).
- `@Redirect` на приватный `getTotalCookTime` в `setItem` → `cookingTotalTime = ванильное + разморозка`. Так как это значение уходит в клиент как `ContainerData` слот 3, ванильная полоска прогресса **честно замедляется**, без своего GUI.
- `burn(...)` для еды → приготовленное **пишется в тот же слот 0**, слот результата для еды не используется. Не-еда идёт ванильным путём.
- Доступ к приватному методу — через `FurnaceCookTimeInvoker` (`@Invoker`), с фолбэком 200 тиков, если аксессор когда-нибудь переименуют.

## 6. Полка

- Блок `eternalsnow:food_shelf`, 5 крючков, `noCollission` (коллизии нет, но `getShape` тонкий — иначе не прицелиться).
- Крючок = ближайший к лучу взгляда, а не «в какой попал»: точка пересечения луча с `getShape()` проецируется на ось полки.
- ПКМ с едой — повесить; ПКМ/ЛКМ пустой рукой по занятому крючку — снять. Пустой крючок + любой предмет в руке — вешаем.
- Рендер — **оригинальная модель предмета** (`ItemRenderer.renderStatic(..., ItemDisplayContext.FIXED, ...)`).
- Сломал — всё выпало (`dropContents`), ничего не пропадает.
- Вешать можно еду, зелья, термос, кружки.

## 7. Теплоёмкость дома (пункт 5, отдельное изменение)

Убрано:
- `ROOM_TAU_SCALE = 250` как «магический» коэффициент (осталась одна откалиброванная константа, и это честно написано в коде);
- вилка `ROOM_TAU_MIN = 600 … ROOM_TAU_MAX = 7200` (30 с…6 мин);
- `roomComfortCeilingC = 26` из физики (поле оставлено только для чтения старых сейвов);
- `elapsed` больше не режется константой 7200 — предел считается из самой медленной комнаты в кэше.

Исправлено:
- **теплоёмкость стены теперь считается по слоям**, а не один раз на грань. Раньше второй слой уменьшал утечку, но не добавлял массу — поэтому «толще» не значило «теплее».

Результат (5×5×3, одна клетка толщины, если не указано иное):

| Дом | τ | Через 10 мин без огня (улица −25) |
|---|---|---|
| Доски | 65 с | −25.0 °C |
| Камень | 2.1 мин | −24.6 °C |
| Бревно | 2.9 мин | — |
| Бревно в 2 блока | **11.4 мин** | −4.2 °C |
| Камень + шерсть | 8.2 мин | — |

Дом **всегда** остывает до улицы — это свойство релаксации, а не константы. Разница только во времени, и она определяется стройкой.
